# Step 02 — Feature lists (cross-batch alignment)

Turns raw LC-MS/MS runs into one feature table per ionisation mode
(Supplementary Method 1). Samples were measured in **6 independent batches**;
each batch was first processed on GNPS as an FBMN job, then this step aligns
the six batches into one table so the same molecule gets the same `feature_id`
everywhere.

## What happens inside

Both modes: raw mzML → **MZmine 4.9** feature detection per batch (IIMN
workflow) → **GNPS2 FBMN** per batch → RT drift correction → cross-batch
consensus. Positive and negative mode use **different alignment
implementations**, documented below.

**Positive mode** (`alignment_pipeline_POS.py`, reference-centric):

| Sub-step | What it does |
|---|---|
| 1. Anchor discovery | Features present in ≥3 of 6 batches (5 ppm, ±2 min) — >15,000 anchors |
| 2. RT drift | Drift of each batch vs reference batch OE23-POS |
| 3. LOESS correction | Single-pass LOESS smooths the drift (residual 0.35–0.52 min) |
| 4. Consensus | Every batch matched **to the reference** (5 ppm, ±0.5 min); RT window 1.5–25 min |
| 5. Library integration | GNPS matches + families merged → combined TSVs |

**Negative mode** (`neg/rt_correction_v2.py` + `neg/align_consensus.py`, cascade):

| Sub-step | What it does |
|---|---|
| 1. RT correction v2 | **Iterative LOWESS** (10 rounds, tightening tolerance, MAD outlier rejection) per batch vs OE23-NEG |
| 2. Cascade consensus | Consensus seeded from OE23-NEG, then each batch (largest→smallest) matched **to the growing consensus**; biological samples only; RT window 1.5–21 min |

**Result:** 273,248 features × 263 samples (positive); 122,571 × 200 (negative).
The NEG run receipt (`neg/alignment_stats.csv`) ends at exactly 122,571
features.

Reads: ← 6 FBMN batch results from GNPS (quantification, library matches,
cluster summaries per batch) + sample metadata.
Used by: → 03 biomarker atlas and everything after it.

## Files here

| File | What it is |
|---|---|
| `fbmn_batches_POS.csv`, `fbmn_batches_NEG.csv` | The 12 batches with their **GNPS2 task IDs** |
| `alignment_pipeline_POS.py` | POS producer |
| `neg/rt_correction_v2.py`, `neg/align_consensus.py` | NEG producers |
| `neg/alignment_stats.csv` | NEG run receipt — cascade ends at 122,571 features |
| `neg/neg_sample_metadata.csv`, `neg/excluded_samples.csv` | NEG sample mapping: biological vs excluded columns |
| `neg/download_gnps2_results.py` | Fetches the 6 NEG FBMN task exports |
| `mzmine_neg/*.mzbatch` | MZmine parameter files for all 6 NEG batches |
| `mzmine_pos_oe23/` | MZmine batch file for the OE23-POS reference batch (MZmine 4.9.0) |
| `all_library_matches_combined.tsv` | GNPS library matches merged across batches |
| `columns_POS.txt`, `columns_NEG.txt` | Column lists of the two consensus tables |
| `pos_gnps2/` | GNPS2 submission/download automation for POS |

## Files registered, too big for git (see `data_registry/registry.csv`)

regenerated by rerunning the scripts on the FBMN exports. Raw mzML files
